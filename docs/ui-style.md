# 智能客服系统 · 界面风格
status: Confirmed

适用平台：内部 Web。本次界面：登录、员工端、知识库页面、客服工作台。  
依据：`docs/PRD.md` REQ-001～REQ-007 及对应 AC；等待与失败按 `docs/tech-spec.md`、D-001 方案 B。无用户提供的品牌或已有界面，首次设计。  
设计基准视口：1440×900；适配 1280～1440，低于 1280 保持单栏可读、三端导航仍可用。不另做移动端 APP 布局。

## 一、设计目标与风格判断

### 产品类型与体验目标

内部 IT 服务台。同一账号在三个互斥工作台之间切换：员工把问题问清楚并看到带来源的回答；知识库放下文档后可离开，回来看进度和结果；客服立刻看到待接入对话并回复。信息密度中等偏高：对话要好读，工单列表要一眼分出状态。业务范围见 PRD，不在此扩展功能。

体验目标：主区永远是「当前正在处理的事」（对话、入库结果或当前工单），来源、进度和失败用短标签与文案说清，不靠装饰吸引注意。

### 视觉风格

名称：**冷静服务台**。低饱和蓝灰底、白卡片、青绿主操作。对话像内部工具而不是消费聊天；来源用小色标区分 FAQ / 闲聊 / 知识问答。避免营销横幅、大圆角拟物、霓虹渐变和自动深色主题。

关键取舍：员工端给对话留宽；客服端左侧工单列表更紧、右侧对话仍可读。三端共用顶栏，不各做一套皮肤。

### 关键 UX 规则

1. **输入区钉在底部**：员工端与客服回复区不随消息列表被挤出视口；消息区单独滚动。见 UI-02、UI-04。
2. **来源先于正文**：自动回复先出现 FAQ / 闲聊 / 知识问答标记，再逐字出正文；历史里是完整一条。客服消息不带来源三种标记。见 UI-02。
3. **工单状态只在客服端**：员工只见「正在等待人工客服」或客服正文。见 UI-02、UI-04。
4. **入库可离开**：提交后列表立即出现「排队中/处理中」，可切到其它端；回来仍能看到进度、成功详情或失败原因。见 UI-03。
5. **三端互斥**：顶栏同一时刻只高亮一个入口，只渲染当前页，隐藏页不占位。刷新后地址、高亮与内容一致。未登录只显示登录页。

文字与背景：Text 在 Surface/Canvas 上；主按钮白字配 Primary。焦点环 `2px solid Primary`，偏移 2px。禁用降低对比并禁止点击，不只改透明度。

### 字体与字阶

| 用途 | 字体与回退 | 字号 | 字重 | 行高 / 字距 |
| --- | --- | --- | --- | --- |
| 页面标题 | `"Source Han Sans SC", "Noto Sans SC", "PingFang SC", sans-serif` | 20px | 600 | 28px / 0 |
| 区块标题 | 同上 | 16px | 600 | 24px / 0 |
| 正文 | 同上 | 14px | 400 | 22px / 0 |
| 辅助信息 | 同上 | 12px | 400 | 18px / 0 |
| 来源标签 | 同上 | 12px | 600 | 16px / 0.02em |

中英数混排同一字体栈。标签 code（如 hardware）不对员工展示，界面写「硬件设备」。不单独定义代码等宽，除非知识库展示原文片段：可用 `ui-monospace, Menlo, monospace` 12px。

### 布局、间距与形状

- 外壳：顶栏高 56px，左右 padding 24px。内容区 `height: calc(100vh - 56px)`。
- 员工端：左栏历史 280px，右栏对话自适应；客服端左栏工单 320px。
- 知识库：上区上传 120px 内，下列表与详情左右 40% / 60%。
- 间距刻度：8 / 12 / 16 / 24。卡片内边距 16px。
- 控件高：主按钮 36px，输入 36px，多行输入最小 44px。
- 圆角：面板 8px，按钮 6px，来源标签 4px，气泡 12px。
- 1280 以下：历史/工单栏可收为 240px；不改为底部 Tab。登录卡宽 400px 居中。

### 层次、阴影与动效

- 顶栏 Surface + 底边 Border，无重阴影。
- 卡片 `0 1px 2px rgba(15,23,42,0.06)`。
- 流式正文无弹跳动画；新消息插入即可。
- 减弱动效：`prefers-reduced-motion` 时流式改为整段出现。
- 不使用全屏模态代替主流程结果。

## 三、全局组件与状态

| 组件 | 外观与全局值引用 | 主次层级 | 适用状态及表现 |
| --- | --- | --- | --- |
| 主按钮 | Primary 底、白字、高 36px、圆角 6px | 每区仅一个主动作 | 默认 / hover Primary-hover / active 略深 / focus-visible 焦点环 / disabled Disabled |
| 次按钮 | Surface、Border、Text | 转人工、关闭、取消类 | 同五态；等待人工时「转人工」禁用 |
| 文本输入 | Surface、Border、正文 14px | 登录与单行回复 | 聚焦边框 Primary；错误边框 Error + 下方错误文案 |
| 多行输入 | 同输入，最小高 44px | 员工提问、客服回复 | 滚动发生在输入框内，不撑高整页 |
| 顶栏导航 | 未选 Text-muted；选中 Primary + 底边 2px | 三端互斥 | hover 文字变 Text；当前页不可再点进自己 |
| 来源标签 | FAQ/Chat/Knowledge 色底浅 12% + 对应色字 | 自动回复必有，客服消息无 | 出现在气泡顶部，先于正文 |
| 状态点 | Success/Warning/Error 8px 圆点 + 文字 | 知识库列表、客服工单 | 排队中 Warning「排队中」；处理中 Warning「处理中」；成功 Success「已生效」；失败 Error + 原因 |
| 对话气泡 | 员工 Primary 浅底靠右；系统 Surface+Border 靠左；客服 Agent 浅底靠左 | 主阅读区 | 长文本折行，不横向撑破 |
| 等待横幅 | Wait 浅底 + Wait 文字 | 仅员工端转人工未关闭 | 文案「正在等待人工客服」；接入后改为「人工客服处理中」 |
| 列表行 | 上对齐，行高至少 48px，Border 底分 | 历史、文档、工单 | 选中左侧 3px Primary；长文件名中间省略 |
| 错误条 | Error 浅底 + Error 字 | 登录失败、格式拒绝 | 留在表单上方，不清已填内容 |

加载：列表用骨架 3 行，不挡输入区。空状态：一句说明 + 当前页主操作（如「还没有会话，在下方提问」）。成功：知识库状态变「已生效」，不弹成功大窗。

## 四、界面清单与页面设计

索引：UI-01 登录 · UI-02 员工端 · UI-03 知识库页面 · UI-04 客服工作台。原型：`docs/prototypes/01-login/index.html` 等，开发共用外壳见各页布局。

### UI-01 登录

- **依据与目标**：REQ-001，AC-001、AC-002。用内部用户名密码进入三端。原型：`docs/prototypes/01-login/index.html`。
- **布局结构**：无三端顶栏。Canvas 居中 Surface 卡片 400px。阅读顺序：标题 → 错误条（若有）→ 用户名 → 密码 → 登录。窄屏卡片全宽减 32px。
- **内容呈现**：标签在字段上方。无注册、无第三方登录。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 卡片标题 | 页面标题 | 智能客服系统 | 静态 | 页面标题 |
| 表单 | 文本输入 ×2 | 用户名、密码 | 密码掩码；回车提交 | 文本输入 |
| 主操作 | 主按钮 | 登录 | 空字段禁用；成功进员工端 | 主按钮 |
| 失败 | 错误条 | 账号无效或需要登录 | 保留已输入用户名 | 错误条 |

- **状态与操作结果**：空表 → 登录禁用。填写后登录 → 成功进入 UI-02 且可切三端；失败 → 错误条，不能进任一端。未登录打开其它原型地址 → 回到登录。
- **示例数据与文案**：演示账号 `demo` / `demo`（仅设计演示）。错误：「账号无效或需要登录」。
- **页面例外**：无顶栏。

### UI-02 员工端

- **依据与目标**：REQ-002、REQ-004、REQ-005；AC-003、004、008～011、016～018、023。提问、看历史、转人工。原型：`docs/prototypes/02-employee/index.html`。
- **布局结构**：共用外壳（顶栏：员工端 / 客服工作台 / 知识库）。内容区左历史、右对话。右栏自上而下：会话标题、消息滚动区、等待横幅（条件）、输入区（含转人工）。消息区 `flex:1; overflow:auto`；输入区不滚动出视口。窄屏历史可折叠，默认仍显示当前会话。
- **内容呈现**：历史按最近在上，标题取首条问题截断。消息：员工右、系统/客服左；自动回复顶上来源标签。长消息折行。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 顶栏 | 导航 | 三端名称 | 当前「员工端」 | 顶栏导航 |
| 左栏 | 列表行 | 历史会话 | 点击切换；高亮当前 | 列表行 |
| 消息 | 对话气泡 | 问答与来源 | 流式时先标签后逐字 | 气泡、来源标签 |
| 等待 | 等待横幅 | 正在等待人工客服 / 人工客服处理中 | 仅未关闭转人工 | 等待横幅 |
| 输入 | 多行输入 + 主按钮发送 + 次按钮转人工 | 当前问题 | 空发送禁用；转人工中发送仍给客服；转人工禁用直至可再转 | 多行输入、主次按钮 |

- **状态与操作结果**：发送 → 员工气泡立刻出现，系统先来源再逐字。FAQ/闲聊/知识问答/兜底/无法回答均带来源。点转人工 → 横幅「正在等待人工客服」，客服端立即多一条待接入（跨页）。客服接入后横幅改「人工客服处理中」，客服消息立即出现且无来源三种标记。关闭工单后横幅消失，恢复自动回复。历史打开看到当时完整内容与来源。
- **示例数据与文案**：会话「VPN 提示认证失败」：FAQ 答「先检查账号是否锁定，再重试连接公司 VPN。」会话「今天天气真好」：闲聊。超范围：「当前问题超出知识服务范围，你可以点击转人工。」无法回答：「现有知识无法回答」，提示可转人工。
- **页面例外**：无。

### UI-03 知识库页面

- **依据与目标**：REQ-003、REQ-007；AC-005、007、019、020、024。上传后可离开，回看进度、标签、FAQ。原型：`docs/prototypes/03-knowledge/index.html`。
- **布局结构**：共用外壳，当前「知识库」。上区上传；下列表 | 详情。列表单独滚动，详情单独滚动。上传区不随列表消失。
- **内容呈现**：列表行：文件名、状态点+文字、进度（仅进行中显示「处理中 40%」这类说明，帮助判断还在跑，不是技术监控大盘）。详情：对象/诉求中文名、分块摘要、抽出的 FAQ 问答。失败只显示原因。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 上传 | 主按钮 + 文件选择 | PDF/Word/Markdown/txt | 选中即提交；不支持格式当场错误条 | 主按钮、错误条 |
| 列表 | 列表行 | 文档与状态 | 点击看详情；切走再回来仍在 | 列表行、状态点 |
| 详情 | 正文 + 标签 | 分块、标签、FAQ | 成功才完整；失败只原因 | 正文、Success/Error |

- **状态与操作结果**：不支持格式 → 当场「不支持该格式」，列表不新增。支持格式 → 立即出现「排队中」，可切员工端；回来变为处理中或已生效/失败。已生效后员工端立即可被 FAQ 或知识问答用到。无「确认入库」按钮。
- **示例数据与文案**：`VPN认证失败.md` 已生效，对象「网络与远程接入」、诉求「故障与异常排查」，FAQ「VPN 提示认证失败怎么办」。演示「空文件」失败：「无法提取正文」。
- **页面例外**：无检索框（员工也不能在此之外的员工端检索）。

### UI-04 客服工作台

- **依据与目标**：REQ-004、REQ-006；AC-008～015。待接入/处理中/关闭，接入、回复、关闭。原型：`docs/prototypes/04-agent/index.html`。
- **布局结构**：共用外壳，当前「客服工作台」。左：三个状态切卡 + 工单列表（列表上对齐独立滚动）。右：上下文对话 + 底栏回复（仅处理中可发）与关闭。输入区钉底。窄屏左栏 240px。
- **内容呈现**：工单行显示员工首问截断 + 状态中文（待接入/处理中/关闭），不把内部枚举 `queued` 直接写出。对话含转人工前的自动回复，便于接着答。
- **组件清单**：

| 区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用 |
| --- | --- | --- | --- | --- |
| 状态切卡 | 次级导航 | 待接入 / 处理中 / 关闭 | 只改列表过滤，不新开页 | 顶栏导航同级字阶 |
| 工单列表 | 列表行 | 新单立即插入顶部 | 点选打开 | 列表行、状态点 |
| 对话 | 对话气泡 | 上下文 | 只读历史 + 新消息 | 气泡 |
| 接入 | 主按钮 | 接入 | 仅待接入显示 | 主按钮 |
| 回复 | 多行输入 + 主按钮 | 客服正文 | 处理中可用；关闭后禁用 | 多行输入 |
| 关闭 | 次按钮 | 关闭工单 | 处理中可用；关闭后该单不能再回 | 次按钮 |

- **状态与操作结果**：员工转人工 → 待接入立即出现。接入 → 该单到处理中，员工横幅变化。回复 → 员工马上看到。关闭 → 关闭列表可见，回复区禁用；员工端恢复自动回复。不接入则待接入保持。
- **示例数据与文案**：待接入「VPN 提示认证失败」；回复示例「我帮你看一下账号锁定情况。」
- **页面例外**：左栏比员工端略宽，便于扫状态。

## 五、使用与验收

应采用：三端顶栏互斥；对话输入钉底；来源标签用 FAQ/Chat/Knowledge 色；工单中文状态只在客服端；入库状态用状态点+文字。  
应避免：员工端展示待接入/处理中/关闭；用弹窗代替发送/接入结果；为凑布局加搜索筛选；自动回复与客服用同一来源标签。

文档检查：四页均有布局、组件、状态与示例；色值与字阶只在全局表定义；长文本折行、空态、失败态已写。

### 原型验证记录

- 方式：浏览器实际打开 `http://127.0.0.1:8765/Projects_Repo/Customer_Service/docs/prototypes/` 下各页；视口约 1440 宽。登录提交因自动化不能向密码框输入，改用 `?preview=1` 进入已登录态；登录页本身做了画面检查。
- UI-01 登录：居中卡片、主按钮、演示说明可见；密码框提交与错误账号未在浏览器里点过。
- UI-02 员工端：顶栏「员工端」高亮；历史与对话分区；输入钉在底部；FAQ / 闲聊来源标签正确；点转人工后出现「正在等待人工客服」，不展示工单状态。
- UI-04 客服工作台：待接入列表立即有该会话；接入后可回复；员工端马上看到客服灰气泡且无 FAQ/闲聊/知识问答标记，横幅为「人工客服处理中」。
- UI-03 知识库：已生效文档可见中文标签、分块与 FAQ；上传不支持格式、异步进度回看未用真实文件选择器跑通。
- 未验：1280 窄屏、关闭工单后恢复自动回复、超长列表滚动、错误登录文案。
- 结论：已验主链路与布局符合风格文档；未验项不宣称通过。风格与原型待用户合并确认。
