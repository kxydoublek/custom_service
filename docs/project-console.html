登录

/login

内部账号登录。成功后进入员工端；失败留在本页并显示错误条。

提交账号密码登录

源码已核对

触发：登录页填写用户名和密码后点「登录」。用户名需非空 trim，密码非空，提交中按钮禁用。

输入：username string、password string（JSON body）。

输出：成功：写入 access_token，跳转 /employee。失败：错误条「账号或密码不正确」，密码框标红，不进三端。

主流程

  1. 1. 用户
    提交登录表单
    数据：username、password
    分支：缺一项则按钮禁用，不发请求
  2. 2. 前端 LoginPage / AuthProvider
    调用 login() → POST /api/auth/login
    数据：Authorization 不带 Token
  3. 3. 后端 AuthService
    按用户名查库并用 bcrypt 校验密码，签发 JWT
    数据：access_token、token_type=bearer、user{id,username}
    分支：用户不存在或密码错 → 401 UNAUTHORIZED，文案不区分哪一项
  4. 4. 前端
    setAccessToken 后 replace 到 /employee
    数据：Bearer 供后续请求
    分支：Axios 非登录接口 401 会清 Token 并跳 /login

接口：API-001、API-002

算法：ALG-AUTH

恢复登录与进入三端

源码已核对

触发：打开站点或刷新。未登录访问 /employee、/agent、/knowledge 会回到 /login。

输入：localStorage 中的 access_token（若有）。

输出：有效令牌：authenticated，可进三端外壳（顶栏员工端/客服工作台/知识库互斥高亮）。无效：anonymous，停在或回到登录。

主流程

  1. 1. 前端 AuthProvider
    启动时若有 Token 则 GET /api/auth/me
    数据：Authorization: Bearer
    分支：无 Token → 直接 anonymous
  2. 2. 后端 get_current_user
    解码 JWT 并查用户
    数据：UserPublic id/username
    分支：缺凭证/坏 Token/用户不存在 → 401 请先登录
  3. 3. 路由器
    RequireAuth 保护三端；已登录访问 /login 改去 /employee
    数据：顶栏三端 Link
  4. 4. 前端
    AuthProvider.logout 会 POST /api/auth/logout 并清 Token、关 WS
    数据：logged_out=true；服务端无黑名单
    分支：顶栏未放置退出按钮，页面上没有该触发，仅服务与 Context 已实现

接口：API-002、API-003

算法：ALG-AUTH

提问并看自动回复

源码已核对

触发：输入框发送。发送中到 SSE done/error 前禁用。

输入：content 去掉首尾空白；上限 message_max_chars 源码默认 2000。

输出：先出现用户消息；若 stream=true，SSE meta 带来源（FAQ/闲聊/知识问答）再 delta 逐字，done 后落成一条完整助手消息。人工进行中 stream=false，不自动回复。

主流程

  1. 1. 员工
    发送问题
    数据：content
    分支：无当前会话则先 POST /conversations
  2. 2. 前端
    POST /conversations/{id}/messages {content}
    数据：返回 user_message、handoff_state、stream、assistant_message 恒为 null
    分支：stream=false 结束忙状态；true 则 fetch SSE
  3. 3. 后端 QaService
    校验空/超长、generation_lock、是否已有未关闭工单
    数据：有未关闭 ticket → 只落 user，stream=false，并在非流路径 commit 后推 message.created
    分支：已有 lock → 409 请等待当前回复结束
  4. 4. 前端
    GET /conversations/{id}/assistant-stream?after_user_message_id=
    数据：Accept: text/event-stream；事件 meta→delta→done 或 error
    分支：prefers-reduced-motion 时不拼接 delta 文本，仍等 done
  5. 5. 后端 stream_assistant_reply
    FAQ → 分类 → 闲聊流 / 超范围切段 / 标签召回后知识问答流
    数据：来源 faq | small_talk | knowledge_qa
    分支：见 ALG-QA

接口：API-010、API-017

算法：ALG-FAQ、ALG-QA、ALG-RETRIEVE

接入、回复与关闭

源码已核对

触发：待接入点「接入」；处理中输入回复并发送或点「关闭」。已关闭无操作区。

输入：ticket_id；回复 content 去空白，上限同消息上限。

输出：接入后 status=processing；回复得到 role=agent 的消息（无来源标签）；关闭后 status=closed，员工 handoff 回到 none。

主流程

  1. 1. 客服
    接入
    数据：POST /tickets/{id}/accept
    分支：非 pending → 409 无法接入
  2. 2. 后端
    mark_processing 并广播 ticket.accepted + handoff.changed=in_progress
    数据：accepted_at
  3. 3. 客服
    回复
    数据：POST /tickets/{id}/messages {content}
    分支：非 processing → 409 不能回复；空/超长 → 400 请输入要发送的内容
  4. 4. 后端
    落 role=agent 消息并 WS message.created 给员工当前会话
    数据：source=null
  5. 5. 客服
    关闭
    数据：POST /tickets/{id}/close
    分支：已关闭 → 409 已关闭

接口：API-014、API-015、API-016、API-018

算法：ALG-TICKET

ALG-INGEST 入库后台任务

上传校验后的异步状态机：抽正文、按字符分块、批量打标、向量、抽 FAQ、成功生效或回滚。

源码已核对

步骤
  1. 扩展名映射 pdf/docx/markdown/txt；超 upload_max_bytes 或未知扩展名在提交阶段失败，不建行。
  2. 建 queued 行，文件写到 upload_dir/{uuid}_{filename}，立即返回 API-004，asyncio 任务限时 ingest_job_timeout_seconds。
  3. extracting：pypdf（加密 PDF 视为空）、python-docx、txt/md 先 UTF-8 再 GBK。空正文 → failed「无法提取正文，文档未入库」。不提供 OCR，不解析 .doc。
  4. chunking：先按空行切段；段长超过 chunk_size_chars 则按字符滑动，窗口=chunk_size_chars，重叠=chunk_overlap_chars，步长 max(1, size-overlap)。单位是字符不是 token。
  5. tagging：taxonomy JSON + 提示 m001_tagging.txt，按 tag_batch_size 条调用 chat_json(purpose=tagging, temperature=0.1)。只保留 taxonomy 内的 object/request code；实体 type 仅 product/device/resource。全部块都无对象且无诉求 → 入库失败。
  6. embedding：chunk 文本走 embed_texts；httpx 路径每批最多 10 条。
  7. faq_extracting：原文截断 faq_source_max_chars，m002_faq.txt（替换 faq_max_per_document），chat_json purpose=faq temperature=0.2；再对 question 向量化。
  8. 同一事务先删旧 chunks/faqs 再写入，文档标 ready、progress=100，推 progress 与 document.ready。任一步失败：删 chunks/faqs、标 failed、删未完成原文、推 failed。不出现半可检索。
  9. 进程启动 fail_interrupted_ingests：仍 queued/processing 的标 failed「入库中断，请重新上传」并删文件，不自动续跑。
分支与筛选
  • 有 LLM Key：llm_http 打真实百炼；无 Key：同一函数走本地 Mock，ingest 不另开通道。
  • 阶段进度 queued0 extracting10 chunking25 tagging45 embedding70 faq_extracting90 ready100。
  • 超时与 LlmHttpError 对用户都是「入库失败，请重新上传」。

结果选择

仅 status=ready 的文档其 chunks/faqs 可被列表计数与问答召回。

失败边界
  • 扫描件/加密 PDF/空文档 → 无法提取正文。
  • 打标全空或模型失败 → 入库失败并回滚。
  • 不读取用户上传内容来填写本页。
