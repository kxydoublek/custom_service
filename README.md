# 智能客服系统

企业内部 IT 服务台。员工用内部账号登录后提问；系统按 FAQ、闲聊、知识问答处理，答不了再由员工点击转人工。知识由知识库管理端入库，成功后立刻对提问生效。

同一账号可在三个工作台之间切换，不区分多用户角色。

## 产品能力

### 登录与三端入口

未登录不能使用。用预设内部账号（用户名 + 密码）登录后，顶栏可进入：

| 入口 | 给谁用 | 能做什么 |
| --- | --- | --- |
| 员工端 | 提问的员工 | 对话、历史会话、点击转人工 |
| 知识库 | 放文档的人 | 上传文档、回看入库进度和结果 |
| 客服工作台 | 人工客服 | 接入工单、回复、关闭 |

### 员工提问

员工在当前会话发消息后，系统按固定顺序处理，**先标明来源，正文再逐字出现**：

1. **FAQ**：命中已抽出的原问，或意思相近的问法 → 标明「FAQ」，直接给出该答案。
2. **闲聊**：与企业 IT 无关的寒暄 → 标明「闲聊」，直接回复，不查知识库、不建工单。
3. **超范围**：信息不足、超出企业 IT、或要查某张工单/申请/权限的实时状态 → 标明「知识问答」，统一回复「当前问题超出知识服务范围，你可以点击转人工。」不追问、不查实时数据。
4. **知识问答**：其余业务问题先识别对象/诉求标签，**只在匹配标签的知识分块里召回**，再生成回答。范围内没有对应知识时，回复「现有知识无法回答。你可以点击转人工。」

多轮对话只用当前会话已提供的信息，不用跨会话记忆，也不做长期用户画像。中途离开再打开该会话，看到的是完整一条回复。

员工端能打开本账号的历史会话，看到当时的问答、来源标记，以及转人工后的客服回复。员工端没有知识检索或上传入口，也不展示工单状态。

### 知识入库

在知识库提交 PDF、Word、Markdown 或 txt 后，系统先收下文件，提交人可以离开或切换到其它入口。后台完成：提取正文 → 分块 → 打对象/诉求标签 → 写入向量检索库 → 抽出 FAQ。

再打开知识库页可以看到排队中、处理中、成功或失败。入库成功后，标签和 FAQ **立即**对员工提问生效，无需再确认。不支持的格式当场拒绝，不入库。抽不出正文时文档不会进入可检索状态，回来也能看到失败原因。

### 转人工与工单

转人工只在员工点击后发生，系统不会自动转接。

- 员工点击后看到「正在等待人工客服」，看不到工单状态；同一会话在待接入或处理中时不会再开第二张单。
- 客服工作台立即出现待接入工单和此前对话；客服自行决定是否接入。
- 接入后工单变为处理中，员工马上看到客服消息；此期间 FAQ / 闲聊 / AI 停止作答，客服回复不带来源三种标记。
- 客服关闭后该工单不能再回复；该会话恢复由 FAQ / 闲聊 / 知识问答处理。再次转人工会生成新工单。
- 客服不接入则工单保持待接入，员工持续看到等待提示。不设员工取消、员工关闭或自动超时关单。

工单状态只在客服工作台展示：**待接入 / 处理中 / 关闭**。

## 提问处理流程

```text
员工发消息
  ├─ 已转人工且未关闭 → 只由客服回复
  └─ 自动回复
        ├─ 原问或相近问命中 FAQ → 来源：FAQ
        ├─ 闲聊 → 来源：闲聊
        ├─ 信息不足 / 超出 IT / 需实时数据 → 来源：知识问答（统一兜底）
        └─ 业务问题
              → 识别对象、诉求标签
              → 只在匹配范围内召回
              → 能答：来源：知识问答
              → 不能答：来源：知识问答，提示可转人工
```

一条完整例子：登录 → 在知识库上传「VPN 认证失败」文档并离开 → 回来看到入库成功 → 员工问「连不上公司 VPN，提示认证失败」→ 先标明 FAQ 再出答案。问「今天天气真好」→ 标明闲聊。问明确的硬件故障且 FAQ 未命中 → 按标签缩小范围后知识问答。问「我那张报修单现在办到哪了」→ 超范围兜底。需要人工时点「转人工」→ 客服接入后只由客服回复，员工马上看到。

## 企业 IT 标签

入库标注和提问识别使用同一套标签，完整定义见 [`docs/tag-taxonomy.json`](docs/tag-taxonomy.json)。界面展示中文名，不向员工展示标签代码。

| 对象 | 含义 |
| --- | --- |
| 硬件设备 | 电脑及外接设备的使用、故障、申请与管控 |
| 软件与操作系统 | 客户端、操作系统及驱动的安装、运行与配置 |
| 账号与身份认证 | 账号、密码、登录、锁定与身份验证 |
| 网络与远程接入 | 公司网络、VPN、WiFi、远程连接 |
| 业务系统与共享资源 | 业务系统、代码仓库、共享存储等 |

| 诉求 | 含义 |
| --- | --- |
| 故障与异常排查 | 无法正常使用，希望检查、诊断或恢复 |
| 报修与维护服务 | 需要 IT 介入的报修、重装、送修 |
| 资源申请与变更 | 获得、安装、更换、归还或扩容资源 |
| 权限开通与调整 | 开通、变更或取消使用权限 |
| 操作与配置指导 | 没有明确故障，询问如何使用或配置 |
| 制度与流程说明 | 规定、资格、审批责任、时效或办理渠道 |

实体（具体产品、设备、资源名称）从文本中提取，不是预先穷举的标签。按完整语义识别：出现 VPN 不代表要申请权限；访问失败不一定是权限不足。同一个问题只选一个主要诉求。

## 本次不做

- 多用户账号体系与角色权限、外部客户客服
- AI 自动转人工、为补全信息而追问
- 查询实时工单 / 申请 / 权限，或调用此类工具
- 员工检索或浏览知识库；员工查看或操作工单状态
- 长期用户画像、跨会话记忆
- 评价、通知、移动端 APP

## 本地运行

前端开发端口 **5199**，Vite 把 `/api` 和 `/ws` 代理到后端 **8099**。不要把真实密钥写进本文件。

1. 复制 `backend/.env.example` 为 `backend/.env`，填写 `SECRET_KEY`、`INTERNAL_USERNAME`、`INTERNAL_PASSWORD`。需要真实模型时再填 `LLM_API_KEY`；为空时走本地 Mock，不调用百炼。
2. 复制 `frontend/.env.example` 为 `frontend/.env`（默认 `VITE_API_BASE_URL=/api`，`VITE_WS_PATH=/ws`）。
3. 后端：在 `backend/` 将 `PYTHONPATH` 指到项目根后启动：

   ```bash
   PYTHONPATH=.. uvicorn src.main:app --host 127.0.0.1 --port 8099
   ```

4. 前端：在 `frontend/` 执行 `npm install` 后 `npm run dev`，浏览器打开 `http://127.0.0.1:5199`。
